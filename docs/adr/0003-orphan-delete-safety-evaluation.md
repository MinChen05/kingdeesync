# ADR-0003: 孤儿清理必须先过安全评估与完整性门控

- **状态**：Accepted
- **日期**：2026-08-03（`9488ead` 引入安全阀）；2026-08-27 强化（`1631797`）
- **相关**：`internal/syncengine/orphan_safety.go`、`cursor_orphan.go`、`isWriteComplete`

## 背景

全量同步后的**孤儿清理**会物理删除目标表中源侧已不存在的记录。两类事故驱动本决策：

1. 源侧拉取异常（返回空或半量）时，若直接删孤儿会清空生产表；
2. `inserted` 在 MERGE 后统计恒为 0，全按 update 写入的全量运行被误判为
   "部分写入"，孤儿清理被整体跳过，脏数据滞留。

## 决策

孤儿删除不是写入的附属步骤，而是独立受控动作：

- **完整性门控**：以 `isWriteComplete`（`inserted + updated` 总写入数达标）判断
  写入是否完整，不完整一律不清理。
- **安全评估**（`EvaluateOrphanDelete`）：综合源计数、上次源计数、目标计数、
  孤儿数、重复键、部分写入标志，产出三态决策
  `blocked / auto_approved / approval_required`。源快照为空 → 直接 `blocked`。
- **安全帽**：游标表单孤儿量超过 10% 上限时阻断，转人工审批。
- 快照表单 TRUNCATE 整体重写，无孤儿语义，不做冗余删除。

## 后果

- 正面：拉取异常不会级联为生产数据删除；误跳过有回归测试锁定（`1631797`）。
- 负面：`approval_required` 路径需要人工介入；安全评估输入字段多，
  调整阈值必须同步改测试。
