# 非数据运营中心页面前端重设计方案

**日期：** 2026-04-18

## 目标

在保留现有主壳层与业务逻辑不变的前提下，重新设计除“数据运营中心”以外的五个主页面：

- 同步执行
- 系统设置
- 表单配置
- 调度管理
- 历史记录

本次重设计遵循统一的 Windows 11 设计系统，但页面之间通过布局结构、内容优先级和模块组织方式形成明显差异。同时，必须把分辨率自适应作为硬约束处理，保证 `1366×768` 下完整可用，并在更高分辨率下自然扩展。

## 背景

当前项目虽然已经具备一套 Windows 11 风格的主壳层，但除“数据运营中心”外，其余页面仍存在几个明显问题：

- 多个页面仍然像“同一种模板复制”，职责差异没有通过布局表达出来。
- 固定宽度输入框、固定比例分栏和复用不当的卡片组件，在不同分辨率下容易挤压、重叠或空洞。
- 一些页面的主操作不够突出，信息层级依然偏“卡片堆叠”，而不是针对任务优化过的工作台。
- 页面之间虽然样式接近，但缺乏明确的结构气质，用户切换页面时难以快速感知当前任务模式。

这次改造的重点不是换一层皮，而是让每个页面都更像“为自己的任务专门设计过”。

## 设计约束

本次方案基于已经确认的约束：

- 保留统一的 Windows 11 设计系统。
- 页面差异主要通过布局结构体现，而不是依赖大幅换色。
- 数据运营中心页面不在本次重设计范围内。
- 主壳层保留，最多做必要的自适应增强，不推翻导航和顶栏逻辑。
- 业务行为不改，只重构 UI 布局、视觉层级和控件组织方式。
- `1366×768` 是最低完整可用分辨率基线。

## 总体设计方向

### 1. 同一系统，不同页面骨架

五个页面继续共享同一套视觉基底：

- 浅色 Windows 11 / Fluent 风格背景
- 白色或浅雾面卡片
- 统一圆角、描边、输入框和按钮系统
- 统一的状态色、字级层级、间距节奏和滚动条外观

但页面不再共用高度相似的骨架，而是采用五种不同的页面结构：

- 同步执行：任务驾驶舱
- 系统设置：配置中心
- 表单配置：列表管理页
- 调度管理：状态控制页
- 历史记录：检索结果页

### 2. 布局差异大于视觉差异

页面之间的差异主要来自：

- 模块顺序
- 主次内容比例
- 双栏还是单主列
- 是否突出表格
- 是否突出操作区
- 是否强调状态与反馈

不通过大幅更换主色或视觉风格制造割裂感。

### 3. 分辨率自适应优先

自适应不是补丁，而是设计的一部分。所有页面都必须遵守统一响应式规则：

- `1366×768`：保证完整可用
- `1600×900`：舒展布局
- `1920×1080` 及以上：留白和模块比例自然扩展

为达到这一点，需要减少固定宽高和写死像素，优先使用：

- 可变 `QSplitter`
- 可收缩输入区
- 可换行或堆叠的卡片区
- 具有最小可视高度的日志、表格和列表

## 页面方案

## 同步执行：任务驾驶舱

### 页面定位

同步执行页是最强操作导向的页面，页面气质应接近“驾驶任务”而不是“浏览摘要”。

### 结构方案

- 顶部保留精简的主操作区：测试连接、开始同步、关键模式提示
- 页面主体采用左右工作台结构
  - 左侧：同步范围、同步模式、运行建议、连接反馈
  - 右侧：执行状态、进度、实时日志
- 执行状态区使用专门的紧凑指标卡，而不是复用顶部摘要卡
- 日志区视觉权重低于执行状态，但可视高度必须稳定

### 自适应要求

- 小屏下双栏自动改上下堆叠
- 右侧执行监控区始终优先于说明文案
- 日志区保留最低可视高度，不能被上方卡片挤爆

## 系统设置：配置中心

### 页面定位

系统设置页应更像“配置中心”，强调清晰、稳定、可信，而不是普通表单堆叠页。

### 结构方案

- 主操作区放在页面顶部：测试连接、保存设置
- 摘要区只保留配置来源、目标数据库、推荐流程
- 主体分两大组：
  - 金蝶 API 配置
  - 数据库配置
- 每组内部强化字段对齐与秩序感
- 单条设置项遵循统一模式：
  - 标题
  - 说明
  - 输入组件

### 自适应要求

- 高分辨率下允许字段说明与输入区横向并置
- 小屏下自动切成纵向结构，避免标题、说明、输入框互相挤压
- 数字输入、长地址输入、密码输入都要有不同的宽度策略，而不是统一固定宽

## 表单配置：列表管理页

### 页面定位

表单配置页应是“管理集合”的页面，重点是搜索、筛选、批量管理和列表浏览。

### 结构方案

- 页面顶部主操作区承载：
  - 搜索
  - 批量操作
  - 重置
  - 保存
- 摘要区只保留已选数量、可见结果数量、当前范围
- 列表区占据主要视觉高度
- 底部只保留轻量状态摘要，不再用大段说明占空间

### 自适应要求

- 列表区高度优先级最高
- 搜索框和批量操作区在不同分辨率下宽度可变
- 列表项能保持统一高度和稳定勾选区域
- 小屏下仍然要保证批量操作始终可见

## 调度管理：状态控制页

### 页面定位

调度管理页应表现为“控制面板”，先看状态，再改策略，再看日志。

### 结构方案

- 页面顶部主操作区：启动/停止任务、保存设置
- 摘要区保留自动调度状态、执行间隔、最近执行、下次执行
- 主体分区顺序：
  - 当前状态
  - 调度策略与间隔设置
  - 策略建议
  - 日志
- 日志不是主角，状态与控制优先级更高

### 自适应要求

- 标准分辨率下采用状态区 + 日志区双栏
- 小屏自动转为纵向堆叠
- 状态卡和控制卡必须始终位于首屏主视区
- 日志保留最小高度，但不能反客为主

## 历史记录：检索结果页

### 页面定位

历史记录页是典型的“查询结果页”，核心体验是快速筛选、稳定浏览和顺手导出。

### 结构方案

- 页面顶部主操作区：查询、导出
- 筛选区采用紧凑工具栏式布局，而不是松散卡片化输入区
- 主体内容以结果表格为主
- 分页条固定贴近表格底部
- 摘要卡维持轻量，不抢走表格空间

### 自适应要求

- 筛选区需要从横向排列自动改为网格或两行布局
- 表格必须保住最大可视面积
- 分页按钮始终可见、可点击
- 导出按钮始终靠近查询动作，不漂移到远处

## 统一视觉规则

## 设计系统

本次仍沿用 Windows 11 方向，但会统一并收紧规则：

- 使用同一套圆角体系
- 使用同一套按钮语义色
- 使用同一套输入框风格
- 使用同一套卡片边框和阴影等级
- 使用同一套滚动区和分页样式

## 差异化边界

允许变化的部分：

- 模块顺序
- 模块比例
- 信息密度
- 操作区位置

不允许变化的部分：

- 整体设计语言
- 控件基础风格
- 状态颜色语义
- 文本层级体系

## 分辨率与缩放适配

### 最低基线

`1366×768` 下，五个目标页面必须满足：

- 主操作区完整可见
- 主体内容区不重叠、不溢出
- 列表 / 表格 / 日志至少有一个稳定的可视区域
- 输入框、按钮、分页不被裁切

### 向上扩展

在更高分辨率下：

- 卡片宽度与留白自然变宽
- 双栏比例更舒展
- 日志、列表、表格得到更多展示空间
- 不能因为扩展而产生大面积空洞或不平衡

### Windows 缩放

需要同时考虑 Windows 显示缩放导致的视觉密度变化，因此尽量减少依赖绝对像素高度的设计。

## 技术落地方式

本次重设计继续基于现有 PySide6 结构，不引入新的 GUI 框架。

主要改造点如下：

- 共享骨架能力
  - 适度增强 `Win11PageScaffold`
  - 支持更灵活的主操作区与页面内容结构

- 页面级布局改造
  - 每个页面拥有更贴合自身任务的模块骨架
  - 替换不合适的卡片复用方式

- 样式系统收敛
  - 继续清理不再使用或冲突的旧样式
  - 保证只保留一套统一的 Windows 11 风格样式表达

- 自适应机制
  - 页内 `QSplitter`、输入框宽度、日志 / 表格 / 列表高度均参与响应式调节

## 数据流与行为边界

本次方案只改前端表现，不改变业务行为：

- 同步逻辑不变
- 设置保存逻辑不变
- 默认表单集合逻辑不变
- 调度行为不变
- 历史查询与导出逻辑不变

任何布局和 UI 的变化，都不应改变这些页面的功能结果。

## 错误处理

重设计后，页面仍需保留当前错误处理特性：

- 加载失败能反馈
- 保存失败能反馈
- 测试连接失败能反馈
- 日志和状态在异常场景下仍能稳定显示

不能因为布局重做引入新的异常，例如：

- 页面切换时报错
- 窗口缩放时报错
- 隐藏 / 显示模块时布局失稳

## 测试与验收

## 设计验收

这次方案完成时，需要满足：

- 五个页面都呈现出不同的结构气质
- 页面切换仍然保持统一系统感
- 数据运营中心不被改坏
- 分辨率变化时布局能自然响应

## 技术验收

最低需要验证：

- GUI smoke tests 覆盖五个页面的关键控件可见性
- `1366×768` 离屏渲染验证
- 更高分辨率下关键页面结构不塌陷
- 不再出现组件复用不当导致的文本重叠、挤压、发黑、裁切

## 不在本次范围内的内容

以下内容不在本次方案范围内：

- 数据运营中心页面重做
- 业务逻辑重构
- 新增功能
- 后端接口改造
- 新主题体系
- 暗色主题

## 结论

本次重设计的核心不是“把所有页面做得一样”，而是：

- 让它们属于同一个 Windows 11 系统
- 让每个页面像是为自己的任务专门设计
- 让分辨率自适应从被动兼容变成主动设计

只要按照这个方向执行，五个页面会比当前更有任务感、秩序感和分辨率弹性，同时不会破坏现有业务能力。
