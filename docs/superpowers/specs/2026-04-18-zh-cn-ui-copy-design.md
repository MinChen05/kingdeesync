# 简体中文界面文案统一改造设计

**目标**

将当前 Windows 11 风格桌面应用中仍然存在的英文用户界面文案，统一改为简体中文，并覆盖页面文案、壳层文案、提示框、状态消息、运行日志消息与错误反馈。

## 背景

当前 GUI 已完成 Windows 11 / Fluent 风格结构迁移，但文案层仍处于“英文 + 少量中文混杂”的状态。用户期望当前界面统一为简体中文，而不是仅翻译部分标题或按钮。

现有代码中，文案主要分布在以下位置：

- `src/gui/kingdee_sync_gui.py`
- `src/gui/pages/dashboard_page.py`
- `src/gui/pages/sync_page.py`
- `src/gui/pages/settings_page.py`
- `src/gui/pages/forms_page.py`
- `src/gui/pages/schedule_page.py`
- `src/gui/pages/history_page.py`
- `src/gui/ui_text.py`
- `tests/test_gui_windows11_shell.py`

## 范围

本次改造包含：

- 主壳层导航、顶栏、状态栏、菜单按钮文案
- 六个页面的标题、副标题、说明文案
- 按钮文本、占位文本、状态徽章文本
- 提示框、保存/导出/复制/测试反馈文案
- 页面内运行状态说明、错误提示、日志消息
- 与上述文案直接绑定的测试断言

本次改造不包含：

- 完整国际化框架
- 中英文语言切换能力
- 配置键名、接口字段名、数据库字段名翻译
- 业务逻辑改动

## 术语规则

### 保留英文的专有名词

以下术语默认保留英文，不强制汉化：

- `Kingdee`
- `SQL Server`
- `API`
- `WebAPI`

### 统一翻译规则

- 操作类文案使用简洁桌面应用语气，例如“保存”“测试连接”“导出”
- 状态类文案使用运维可读、简短明确的表达，例如“运行中”“空闲”“需要关注”
- 日志类文案避免口语化、避免过长句，保持排查友好
- 页面标题与模块名统一为简体中文，不保留英文标题作为主显示文案

## 设计方案

采用“共享文案集中 + 页面专属文案就地中文化”的混合式方案。

### 共享文案集中管理

将可复用的按钮、加载态、反馈消息优先集中到 `src/gui/ui_text.py`，包括但不限于：

- 通用按钮文本
- 保存/测试/导出/复制反馈
- 通用状态文案
- 空状态、错误状态、加载状态

这样可以避免同类按钮或反馈在多个页面里出现不同中文说法。

### 页面专属文案就地维护

每个页面自己的说明文案、标题、副标题、业务提示，保留在对应页面文件内翻译，不强行全部抽到共享文本模块。原因是这些文案与页面结构强绑定，抽离后会降低可读性。

适用于就地翻译的内容包括：

- Hero 区标题、副标题
- 页面说明文本
- 特定页面的状态提示
- 页面日志输出内容

### 测试同步更新

现有 smoke test 已承担结构与部分文案回归保护作用。文案中文化后，测试需要同步调整，避免继续绑定英文字符串。

测试更新原则：

- 结构断言继续保留
- 文案断言只保留关键可见文案，不对所有自然语言整句做脆弱断言
- 对日志/提示类文本，优先验证关键中文片段或行为结果

## 受影响模块

### 主壳层

`src/gui/kingdee_sync_gui.py`

需要翻译：

- 顶栏按钮
- 搜索占位文本
- 顶栏状态徽章
- 状态栏说明
- 窗口菜单相关提示

### 页面层

以下页面需要完整中文化：

- `dashboard_page.py`
- `sync_page.py`
- `settings_page.py`
- `forms_page.py`
- `schedule_page.py`
- `history_page.py`

### 共享文案层

`src/gui/ui_text.py`

如果发现已有常量适合扩充，应优先复用，而不是再在页面里硬编码重复中文。

## 交互与布局影响

中文化后，按钮和标签长度普遍会变短，但某些描述性文案会变长。需要特别注意：

- 顶栏按钮宽度是否仍然合适
- summary card 副标题是否出现截断
- schedule/history 的筛选栏是否需要微调
- forms/settings 的说明文字是否需要保持换行

本次允许进行少量与文案长度适配直接相关的布局微调，但不做新的视觉重构。

## 错误处理与日志策略

所有用户可见错误消息统一改为简体中文，但异常对象本身的原始错误内容可原样保留在消息尾部，方便排查。例如：

- 用户提示部分：中文
- 异常详情部分：保留原始异常文本

日志消息同样改为简体中文，但技术名词保持稳定，不影响日志阅读。

## 验证方案

至少执行以下验证：

- `python -m unittest -q tests.test_gui_windows11_shell`
- `python -m compileall -q src/gui/kingdee_sync_gui.py src/gui/pages src/gui/ui_text.py`
- `QT_QPA_PLATFORM=offscreen` 下实例化 `KingdeeSyncGUI`

验证重点：

- 无英文残留在当前用户可见主路径
- 页面与壳层结构不回退
- 提示框/状态/日志消息能正常显示

## 风险

### 风险 1：英文漏改

由于文案分布较散，可能存在隐藏英文文案漏改。

缓解方式：

- 在 GUI 目录中检索可见英文字符串
- 使用 smoke test 补充关键路径断言

### 风险 2：中文化导致测试脆弱

若测试直接绑定整句文案，后续小改字眼也会导致失败。

缓解方式：

- 只对关键文案做断言
- 避免对长段说明文做整句精确匹配

### 风险 3：文案改动带来轻微布局问题

缓解方式：

- 允许本次顺手处理最小必要的宽度/换行调整

## 实施边界

本次交付标准是“当前界面统一为简体中文”，而不是“支持多语言”。如果后续需要中英文切换，应在下一阶段单独设计国际化方案，而不是在本次任务里顺带实现。
