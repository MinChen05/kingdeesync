# GUI 全页面图标系统技术设计

## 结论

采用“本地 SVG 资产 + 集中图标注册表 + 共享渲染助手”的方式重做全 GUI 页面图标。实现顺序先收口图标命名和查找，再替换资产，最后迁移页面调用点。（原因：先建立系统边界可以降低全页面改造遗漏和重复代码风险）

本变更不涉及数据库结构、同步任务逻辑、SQL Server 写入、checkpoint 或配置文件语义。（原因：用户目标是 GUI 图标渲染质量，不应扩大到业务链路）

## 技术方案

### 1. 图标资产

- 继续使用 `assets/icons/` 下的本地 SVG 作为主要图标来源。（原因：PySide6 已具备 SVG 渲染能力，项目打包流程也已包含 assets）
- 图标统一按 24x24 viewBox 设计，常规线条使用一致 stroke width，并保留 2-3 px 光学留白。（原因：保证 16、18、20、24 px 显示时边缘清晰）
- 对导航、动作、状态、指标类图标建立命名约定，例如 `nav-*`、`action-*`、`status-*`、`metric-*`。（原因：资产命名本身应支持审计和测试）
- 仅保留必要的 PNG/ICO 桌面图标；页面内优先使用 SVG。（原因：避免同一语义存在多种渲染来源）

### 2. 图标注册表

- 在 GUI 共享层新增或扩展一个图标注册模块，集中维护 page id、action id、status tone、metric key 到图标资产名的映射。（原因：当前页面本地映射分散，后续维护成本高）
- 注册表提供只读查询 API，例如按页面、动作、状态获取 `QIcon` 或资产路径。（原因：页面代码只关心语义，不关心文件路径）
- 注册表在启动或测试中可枚举所有必需图标，便于校验资产是否存在。（原因：缺失图标应在测试阶段暴露）
- 保留低优先级 fallback，但 fallback 只用于异常容错，不作为正常渲染路径。（原因：防止资产缺失被静默掩盖）

### 3. 页面迁移

- 先迁移全局外壳：侧边栏导航、顶部窗口/工具按钮、页面入口图标。（原因：这些区域跨页面复用，收益最大）
- 再迁移页面内部：仪表盘、同步、计划任务、表单、诊断、日志中心、历史记录、数据源、设置、任务管理。（原因：满足“所有页面”覆盖范围）
- 页面内重复出现超过 2 次的图标展示结构，应抽成公共组件或 helper。（原因：遵守 DRY，避免每页复制相同 QLabel/QIcon/QPixmap 逻辑）
- 不改变页面主布局、字段、按钮行为和同步配置语义。（原因：降低功能回归风险）

### 4. 样式与状态

- 复用现有 Windows 11 shell 样式 token 和 `SizeTokens`。（原因：避免引入第二套尺寸/颜色体系）
- normal、hover、selected、disabled、success、warning、danger、neutral 状态需要统一颜色规则。（原因：图标重做必须保证状态可读性）
- CSS 中与图标相关的选择器应与注册表命名保持一致，避免 CSS-only 图标游离在系统外。（原因：便于全量盘点和测试）

## 风险与处理

- 全页面触达导致 diff 变大：先提交注册表和资产，再迁移调用点。（原因：分层改动更容易审阅）
- SVG 在 Qt 中渲染能力与浏览器不同：避免依赖复杂滤镜、mask、渐变和外部字体。（原因：Qt SVG 支持范围有限，简单线性图标更稳定）
- 选中/禁用态可读性不足：用截图覆盖代表页面并核对深浅背景。（原因：视觉质量需要真实渲染验证）
- 打包后资源缺失：验证 `kingdee_sync.spec` 包含 `assets/icons/`。（原因：桌面端发布风险常出现在打包路径）

## 测试策略

- 增加注册表覆盖测试：所有页面 id、关键 action、状态 tone 均能解析到存在的图标资产。（原因：防止遗漏页面）
- 更新 GUI shell 测试：导航图标尺寸、QIcon 非空、页面构造不报错。（原因：验证窗口初始化链路）
- 更新 CSS/资产测试：确认 CSS 引用的图标文件存在且与注册表不冲突。（原因：避免样式层引用孤儿资产）
- 运行 GUI 相关单元测试和页面构造测试。（原因：验证改造未破坏现有 GUI 行为）
- 进行代表页面截图核对：导航、仪表盘、同步、计划、表单、诊断、日志、历史、数据源、设置、任务管理。（原因：图标美观度和对齐不能只靠断言判断）
- 验证打包资产包含关系，必要时检查 PyInstaller 输出目录。（原因：确保发布产物可加载图标）

## 实施顺序

1. 盘点现有图标调用点和资产清单。（原因：建立完整改造范围）
2. 建立共享图标注册表和渲染助手。（原因：为页面迁移提供稳定接口）
3. 重做并替换核心 SVG 资产。（原因：先提升正常渲染路径质量）
4. 迁移全局外壳和各页面图标调用。（原因：逐层降低页面分散逻辑）
5. 补齐测试、截图验证和打包验证。（原因：全页面视觉改造需要自动化和人工证据结合）
